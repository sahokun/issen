# Internationalization (i18n)

Covers: `src/i18n.rs`, `src/fonts.rs`.

- Default display language is English; switchable to Japanese via
  `config.toml`'s `language` key (`system` / `en` / `ja`).
- `system` resolves from Windows' UI display language
  (`GetUserDefaultUILanguage`) at startup — not the region/format locale,
  so a Japanese-region + English-UI environment doesn't get wrongly
  Japanized. The resolved value isn't written back to the config file.
- No external i18n crate — `src/i18n.rs`'s `Strings` struct is a
  hand-maintained static table per language, since the string count is
  small.
- CJK glyph fallback needs no code at all under GPUI, unlike the
  egui/eframe version (whose `default_fonts` had no CJK glyphs, requiring
  `src/fonts.rs` to load `.ttf`/`.ttc` bytes from `C:\Windows\Fonts`
  — Meiryo etc. — by hand at runtime). GPUI's Windows text system shapes
  through DirectWrite, which performs its own system font-fallback for
  glyphs missing from the chosen UI family whenever a `Font`'s `fallbacks`
  field is left unset (confirmed against `gpui_windows`'s
  `direct_write.rs`, and empirically by typing a Japanese query) — so
  Japanese search results render correctly regardless of which of the
  three selectable UI fonts is active or what the display-language
  setting is (see `docs/architecture/ui-appearance.md`'s "UI font"
  section). `src/fonts.rs` is kept, but now only maps a `UiFont` choice to
  its Win32 family name string — no font-file loading.
